# Dashboard e2e contract

Run `bun run test:e2e` at the repository root. Playwright builds and starts the normal web server at port 4173 and creates disposable SQLite products in the system temporary directory. Four workers limit browser and SQLite contention. The fixture contains both IP families, five granularities, directional traffic, characteristic averages, port cardinalities, IP/protocol counts, MAAD dimensions and spectra, a second populated day, and a separate alerts database. The external-side MAAD dataset also exercises unavailable selections.

The suite uses user-facing controls and rendered chart summaries. Request assertions supplement rendered-data checks for deferred fetching, cancellation, and drilldown. There are no pixel snapshots, canvas pixel reads, or intercepted drawing calls.

## Hooks to preserve during a renderer migration

Keep `data-chart-id`, `data-chart-activated`, `data-chart-sentinel`, deferred-card test IDs, existing canvas accessible names on the replacement graphics, and the named filter groups. The graphics element can become SVG while retaining the following contract:

| Hook                                   | Meaning                                                                                                                                                                                                                                                                                                    |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-testid="chart-surface"`          | Visible graphic with `role="img"`, a chart-specific accessible name, and `aria-description` describing series, finite points, and displayed axes.                                                                                                                                                          |
| `data-chart-rendered="true"`           | A completed renderer pass, including a pass with zero finite points. Also used by the performance harness.                                                                                                                                                                                                 |
| `data-testid="chart-render-state"`     | Sibling summary in the same graphics parent. Published after rendering, removed on destruction.                                                                                                                                                                                                            |
| `data-state="ready\|empty"`            | `ready` requires at least one finite point in a visible series inside the displayed x bounds. All-hidden or zero-point charts are `empty`.                                                                                                                                                                 |
| `data-kind`                            | `line`, `stacked`, or `scatter` for the current chart choice.                                                                                                                                                                                                                                              |
| `data-series-count`, `data-mark-count` | Visible series count and sum of finite visible-series vertices or scatter points. Null, unknown coverage, nonfinite and unpositioned observations are excluded. Coverage summaries report observed/expected ratios rather than lane coordinates. A line vertex counts even when its point glyph is hidden. |
| `data-testid="chart-axis"`             | Text of each displayed axis title. Compact layouts may omit titles.                                                                                                                                                                                                                                        |
| `data-testid="chart-series"`           | Legend or series label with `data-visible`, `data-count`, `data-min`, `data-max`, and `data-total`. Summaries cover finite values inside displayed x bounds, including zero, and remain available for hidden legend entries. No finite values means count 0, min/max `null`, total 0.                      |
| `data-point-x/y`, `data-legend-x/y`    | Optional interaction targets on a series summary, normalized to the graphics bounds. Point target is a finite plotted vertex, legend target is the center of the clickable legend entry. Used to drive real pointer events; tests do not assert coordinate values. Omit unavailable targets.               |
| `data-testid="chart-tooltip"`          | Current rendered tooltip text in the sibling summary, hidden and cleared when no tooltip is shown. Preserve the existing spectrum DOM `role="tooltip"` contract too.                                                                                                                                       |
| `data-testid="chart-card-state"`       | Card lifecycle: `loading`, `error`, `no-metrics`, `empty`, `unavailable`, or `ready`. Card `ready` means its content branch is active; the renderer summary proves finite data actually rendered.                                                                                                          |
| `data-testid="coverage-strip-card"`    | Coverage card retains its test ID and publishes `loading`, `error`, `empty`, or `ready`.                                                                                                                                                                                                                   |

`chart-contract.ts` publishes a renderer-independent DOM summary with memory proportional to series and axes. `ChartPlot.svelte` mounts TanStack through its DOM API in a Svelte attachment and publishes after layout and painting. Sparse charts use SVG. Dense time-spectrum marks paint every observation into a canvas inside the SVG plot group; axes, focus overlays and interactions remain in TanStack. Coverage paths batch their SVG output while retaining native rectangle hit geometry and each bucket observation. Do not synthesize readiness solely from an API response or from a mounted graphics element. The existing spectrum tooltip and loading/empty/unavailable copy remain user-facing contracts.

## Numerical and interaction assertions

The tests verify TCP flows of 100 across both families, 80 for IPv4, 20 for IPv6, and 50 for ingress. Duration averages are 1750 ms combined, 2000 ms for IPv4, and 1000 ms for IPv6. Port counts change from 8 to 2 with family selection. TCP packets and bytes are 1000 and 102400. Daily TCP flow totals change from 100 to 300 as the second populated day enters the range, then to 200 when the first day is excluded. MAAD side/order/measure checks assert fixture values with float tolerance.

Preserve date/grouping/direction/MAAD URL state, history navigation, file context on drilldown and next-file links, brush drilldown, legend visibility, chart order persistence, deferred activation, cached-state recovery, and cancellation of obsolete requests. Missing and unknown coverage must retain the data contract; do not replace null observations with zero in the chart adapter.

The migration regressions cover hovered-bucket totals, singleton positioning, keyboard legend toggles and drilldown, keyboard range selection with cancellation, and a dense spectrum with one accessible interaction target. Empty selections explain why no data is shown. Sources and local metric selections still reset on reload; those choices remain for the redesign.

## Coverage limits

The fixture suite covers the dataset index, dashboard, alerts, file lookup, file detail, and error pages at narrow and wide viewports. Alert failure and clipboard denial tests inject failures; populated alerts use the real temporary alerts database. Browser coverage is Chromium. A separate manual audit of the large read-only performance product supplies the visual reference and exercises multiple real sources. These tests do not measure performance or certify accessibility compliance.
